# Helium evidence triage workflow

## PRE
Inspect repository/file state; recover sources, receipts, hashes, manifests, versions and dispositions. Reconcile coordinates, pressure basis, units, phase, datum, operating mode and ownership. Classify gaps as source, numeric receipt, validation, governance, propagation or recurrence.

## P1 PRODUCE
Produce/consume one decisive immutable object: exact property receipt, grid/path receipt, geometry ledger, pressure locator or mass-flow population. Hash request/source/result and preserve raw values.

## P2 CHALLENGE
Use exact-state primary-reference comparison, lineage classification, residual/tolerance, negative/boundary tests, datum/phase consistency, sensitivity/reverse solve, measured PCA when a governed matrix exists, and BT for remaining evidence priority.

## P3 REENTER
Pass the unchanged receipt/digest to project governance. Return only project disposition states such as ACCEPT/REJECT/DEFER. Parent analysis must not self-promote child truth.

## POST
Rerun deterministic checks; reconcile source/request/calculation/SSOT/artifact hashes; detect recurrence; compare expected readiness with earned DoV.

## Roll-up
Keep formal engineering closure, strict numerical residual closure, runtime readiness, evidence completeness and negotiation/RFI residuals separate.

## Propagate
Push one SSOT digest to schema/Zod, Excel, HTML, graphs/cards/ICDs, evidence registry and release outputs.

## Fan-out
Send governed results to configured federation, PCA, BT, Monte Carlo, cost, V&V, RFI, negotiation or release consumers without allowing them to mutate the governing receipt.
