## Decision: what owns the graph?

CODE PURPLE is the process-agnostic orchestration context governed by
CODEX GLOB and the existing Mesh Closure Controller. A *P0 CODE PURPLE*
posture is the narrower security/admission containment response.

EVERRED 3.0 is ABACUS's specialist process for persistent failure-root
elimination, canonical ownership, bounded repair and verified replay.
It **does not** replace CODEX global method selection.

NEVERGREEN is only a **candidate name** for adversarial false-green
prevention. No independent method or release authority is registered
under that name in the source reviewed for this overlay. Implement
missing/stale/neutral/skip/zero-step rejection as ordinary negative
contracts until its terminology is formally adopted.

## Registered process adapter ordering

Follow CODEX's existing minimum-path controller:

1. **3PR:** Refresh, Probe, Rank; select the first material blocker.
2. **MIP if structural:** Modernize, Innovate, Perpetuate. Run only on a
   measured structural or recurrence gap.
3. **3PC if transactional:** Prepare, Prove, Commit an authorized
   bounded transaction.
4. **3P3 if generalisation is missing:** Preserve/Pin,
   Propagate/Penetrate, Prove/Promote through an independently executing
   consumer. Local DoV precedes cross-repository propagation.
5. **STOP:** No repeated analysis or unnecessary new workflow when
   DoV is satisfied or there is no material evidence change.

`3P*` is a selector/wildcard and is NOT an independently executable
gate. W84 payloads with `moniker=3PR, scheme=3P3` retain their native
schema; do not conflate this payload naming with adapter selection.

DMAIC wraps measured process improvement. SIPOC describes
Supplier/Input/Process/Output/Customer. The extra `.self` re-entry
is a bounded feedback interface, and `PAY_IT_FORWARD` is a separate
consumer-candidate edge, not an inherited approval.

## The six EVERRED objects

- Occurrence: failing step/test on repo+run+attempt+job+event.
- Signature: versioned tool/config-dependent manifestation.
- Root: persistent cause ID after counterfactual investigation.
- Canonical repair: owner, path lease, branch, code and negative test.
- Consumer verification: snapshot, replay, native exact-head receipt.
- Admission: independent security/reviewer and protected policy.

One signature may have several causes; one cause may generate many
occurrences. A failed rerun creates a new occurrence, not an arbitrary
new root. Avoid competing workers on the same canonical mutation files.

## Proof, NEVERGREEN candidate guard and denominators

Keep these units separate: LDAB source files; executed MIP contract
checks; native debugger sessions; Docker port leases; scanner findings;
coverage-covered/eligible lines or branches; accepted repair roots;
admitted integrations. Never sum unlike units as a success score.

- MIP two-pass source repeatability is not LLDB execution.
- Native session proof requires authenticated run/job/session, real
  debugger steps, time-bound port/image and teardown evidence.
- Configured ports are not listening/reachable ports.
- A scoped test pass is not a repository-wide coverage uplift.
- Full and configured scanner counts use different configurations.
- Proposals/worker job successes are not accepted repairs.
- N-10 contains historical checkpoints; metric comparison requires
  matching version/configuration/scope and observed numerators.
- W84/3P3 score determinism and two comparable observed effectiveness
  cycles never replace independent engineering or security approval.
- Missing, stale, neutral, cancelled, zero-step and synthetic evidence
  must never be promoted to PASS.

## P0-P7 and cross-repository ownership

P0: exact-SHA evidence preflight and ownership/policy census.

P1: local source syntax, Ruff/format, targeted safe checks.

P2: canonical producer proof; focused and negative regressions.

P3: bounded, isolated affected-consumer testflight.

P4: native CI, scanner and coverage proof on consumer's actual head.

P5: independent security + eligible review and effective protection.

P6: owner-authorized merge; integrated-main checks and exact readback.

P7: recurrence sentinel and root closure; pay forward portable assets
only after independent consumer acceptance.

CODEX owns global GLOB/mesh and MissionControl/REX candidate roll-ups.
ABACUS owns its CI, LDAB, runtime, repair and security evidence.
QPS owns QPS domain engineering/release decisions. No method receives
authority via telemetry, cross-repository federation or dashboard.

P0 containment may be lifted as a workflow posture without granting
merge admission while `protected=false` or a mandatory gate fails.
